## 日本語

### 追加・変更

- **クライアントの接続先を 5 つまで登録**（設定 → 📶 WiFi）
  - 「接続先の選び方」が**自動**なら、起動したときに周りの WiFi を探し、登録した中で一番電波の強いものに接続します（自宅のルーターと会場のポケット WiFi を両方入れておく、など）。**選択**なら ● を付けたものに接続します。
  - 今までの接続先は 1 つ目にそのまま残ります。パスワードは今まで通り画面に出しません。
- **ホストモードの WiFi チャンネルを選べる**（6〜13 ch、初期値 6 ch）
  - ゴーグル OSD の ESP-NOW が 1 ch を使うので、5 ch 以下は選べません。アクセスポイントは 20 MHz 幅です。
- **UID をバインドフレーズの欄に入れられる**
  - パイロットの「ELRS」欄の右の「UID」にチェックを入れると、送信機の UID（ELRS の設定画面に出る 6 つの数字、例 `210,141,145,12,34,56`。12 桁の 16 進数でも可）をその欄に入れて登録できます。バインドフレーズと同じように扱います。
  - SD のパイロット情報のバックアップ（`pilots.csv` の `uid` 列）にも入り、復元できます。
  - パイロット一覧には UID を出しません（リンクの状態「📶 LQ」「📴 リンクなし」は今まで通り出します）。
- **初期値の変更**：受信ゲイン **15**（前は 30）、Enter（入）**300**（前は 350）、Exit（出）280（変わらず）。新しくパイロットを登録するときもこの値で入ります。
  - 今お使いのタイマーの設定と、登録済みのパイロットの値はそのまま残ります（初期値が使われるのは、設定をしていないタイマーと新しく登録するパイロットです）。

### 修正

- **レースディレクターのスイッチ（スタート・ストップ）の反応が悪い**
  - 送信機はスイッチを切り替えたとき 1 回だけ信号を送りますが、ブリッジは OSD を送るたびに宛先をパイロットの UID に切り替えるため、その間に届いた信号を取りこぼしていました。
  - ブリッジ（[elrs-netpack v2.12](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.12)）が、宛先に関係なくスイッチの信号を聞き取るようにしました。**ESP-NOW ブリッジの書き換えが必要です。**
- **画面から更新したあと、再起動しても古いファームのまま動く**
  - タイマーの再起動は「2 秒間ディープスリープしてから起き直す」作りですが、ESP32 はディープスリープから起きるとき、前回と同じ場所のファームを起動します。そのため新しいファームは電源を入れ直すまで動かず、「ファームと Web 画面のビルドが違います」と出ていました。
  - 新しいファームが書き込まれているときは、リセットで再起動するようにしました。

### 更新方法

- **タイマー（v2.2.2 / v2.2.3）**：設定タブ「⬆️ ファーム更新」→「🔍 最新版を確認」→「⬇️ v2.2.4 に更新」。**今回だけは**、更新後の再起動を古いファームが行うため、再起動のあとシステム情報が v2.2.4 にならなければ、**電源を一度入れ直してください**。次の版からは入れ直し不要です。
- **タイマー（v2.2.1 以前）**：[Web 書き込みページ](https://yanazoo.github.io/FPV-C5-Lap-Timer/) か PlatformIO で書き込んでください。
- **ESP-NOW ブリッジ**：[Web 書き込みページ](https://yanazoo.github.io/FPV-C5-Lap-Timer/) の「ESP-NOW ブリッジ」で書き込むか、PlatformIO で `third_party/elrs-netpack/elrs-espnow-bridge` を書き込みます。

```bash
git fetch && git checkout v2.2.4
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
```

設定とパイロット情報は引き継がれます。

### 動作確認

- PC テストはすべて合格し、S3・C5・ブリッジのビルドを CI で確認しました。
- ブリッジは、`main.cpp` をそのままコンパイルした PC テストで、パイロットの UID で OSD を送っている最中でもディレクターのスイッチを受け取れること、重複を 1 回にまとめること、パイロットの DVR スイッチを渡さないこと、OSD の送り方が前の版と同じことを確かめました。
- ブラウザー（モック）で、WiFi の接続先 5 件・自動／選択・チャンネルの保存と、UID の入力・保存・編集・誤った UID を断ること、新しいパイロットが Enter 300 / Exit 280 で入ることを確かめました。
- 実機（XIAO ESP32-S3）で、v2.2.2 → v2.2.3 のネットからの更新が成功し、電源を入れ直すと v2.2.3 で動くことを確かめました。
- スイッチの反応・WiFi の自動接続・更新後の自動再起動は、実機でこれから確かめます。

## English

### New and changed

- **Up to 5 client networks** (Settings → 📶 WiFi)
  - "接続先の選び方" **automatic** joins the strongest stored network in range at boot (say, the home router and the field's pocket WiFi); **select** joins the one marked ●.
  - The network stored before stays as the first. Passwords are still never shown.
- **Host mode WiFi channel** can be picked: 6–13 (default 6).
  - ESP-NOW for the goggle OSD is on channel 1, so 5 and below aren't offered. The access point is 20 MHz wide.
- **A UID in the bind phrase field**
  - Tick "UID" next to a pilot's ELRS field and type the radio's UID there: the six numbers the ELRS configurator shows, e.g. `210,141,145,12,34,56`, or 12 hex digits. It works just like a bind phrase.
  - The SD roster backup (`pilots.csv`, column `uid`) saves and restores it.
  - The pilot list doesn't show the UID (the link state "📶 LQ" / "📴 リンクなし" is shown as before).
- **New defaults**: receiver gain **15** (was 30), Enter **300** (was 350), Exit 280 (unchanged). New pilots are registered with these values.
  - A timer's saved settings and the pilots already registered keep their values (the defaults apply to an unconfigured timer and to new pilots).

### Fixed

- **The race director's start/stop switch reacted only sometimes**
  - The radio sends the switch once per flip. The bridge moves to each pilot's UID for the OSD, and a flip arriving then was lost.
  - The bridge ([elrs-netpack v2.12](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.12)) now hears the switch whatever its UID is. **Reflash the ESP-NOW bridge.**
- **After an update from the page, the timer restarted into the old firmware**
  - The timer restarts through a 2 s deep sleep, and the ESP32, waking from deep sleep, starts the app it ran before. The new firmware ran only after a power cycle, and the builds were reported as different.
  - With a new firmware waiting, the timer now restarts with a reset.

### Updating

- **Timer on v2.2.2 / v2.2.3**: Settings → "⬆️ ファーム更新" → "🔍 最新版を確認" → "⬇️ v2.2.4 に更新".
  - **This once**, the restart after the update is still done by the old firmware. If the system info doesn't show v2.2.4 afterwards, **power the timer off and on**.
  - Later updates don't need that.
- **Timer on v2.2.1 or older**: use the [web flasher](https://yanazoo.github.io/FPV-C5-Lap-Timer/) or PlatformIO.
- **ESP-NOW bridge**: use the web flasher's "ESP-NOW ブリッジ" button, or PlatformIO with `third_party/elrs-netpack/elrs-espnow-bridge`.

```bash
git fetch && git checkout v2.2.4
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
```

Settings and pilots are kept.

### Verified

- All PC tests pass; the S3, C5 and bridge builds were checked in CI.
- Bridge: PC tests compile the real `main.cpp` against stubs. They show that:
  - the RD's switch is heard while the bridge sends OSD on a pilot's UID;
  - duplicates are passed on once;
  - pilots' DVR switches are filtered out;
  - the OSD output is unchanged.
- In a browser (mock):
  - the 5 networks, automatic or select, and the channel are saved;
  - a UID is entered, saved and edited, and a wrong UID is refused; a new pilot gets Enter 300 / Exit 280.
- On hardware (XIAO ESP32-S3): the online update v2.2.2 → v2.2.3 succeeded, and after a power cycle the timer ran v2.2.3.
- Still to be checked on hardware: the switch response, joining WiFi automatically, and the restart after an update.
