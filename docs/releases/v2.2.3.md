# FPV C5 Lap Timer v2.2.3 — 「ファイルから」の更新でファームが書き込まれない不具合の修正 / Fix for the firmware not written by “from files”

> **Language / 言語:** [日本語](#日本語) | [English](#english)

---

<a name="日本語"></a>

## 日本語

### 修正

- **「ファイルから」で 2 つのファイルを一度に書き込むと、ファームが入らないことがある**：`firmware.bin` と `littlefs.bin` の両方を選ぶと、Web 画面を先に、ファームを後に書き込みます。Web 画面を送った接続が閉じるときに、書き込み中のファームまで止めてしまうことがあり、Web 画面だけ新しくなってファームが古いまま残っていました（システム情報に「ファームと Web 画面のビルドが違います」と出ます）。接続が閉じたときに止めるのは、その接続自身の書き込みだけにしました。
- Web 画面だけを書き込んで再起動しない場合も、新しい Web 画面がすぐ使えるようにしました。

### 対応するファームウェア

v2.2.2 から、受信機とブリッジは変わりません。

| 機器 | ファームウェア |
|---|---|
| XIAO ESP32-S3（タイマー） | このリリース |
| XIAO ESP32-C5（受信機） | FPVGate C5MK（サブモジュール `e62a635`。変更なし） |
| ESP-NOW ブリッジ（XIAO ESP32-C3 / Wrover-E） | [elrs-netpack v2.11](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.11)（変更なし） |
| netpack XIAO（WiFi で使う場合） | [elrs-netpack v2.10](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.10) 以降（変更なし） |
| RotorHazard で使う場合のプラグイン | [vrxc_elrs v1.1.9](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.9)（変更なし） |

### 更新方法

- **v2.2.2 のタイマー**：設定タブ「⬆️ ファーム更新」→「🔍 最新版を確認」→「⬇️ v2.2.3 に更新」で、ネットから更新できます（クライアントモードでインターネットにつながっているとき）。
- **v2.2.1 以前のタイマー**：「ファイルから」でこのリリースの zip の `firmware.bin` と `littlefs.bin` を書き込むか、[Web 書き込みページ](https://yanazoo.github.io/FPV-C5-Lap-Timer/) か PlatformIO で書き込んでください。v2.2.2 以前の「ファイルから」では、念のため `firmware.bin` と `littlefs.bin` を 1 つずつ書き込んでください。

```bash
git fetch && git checkout v2.2.3
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
```

設定とパイロット情報は引き継がれます。

### 動作確認

- PC テストはすべて合格し、S3・C5・ブリッジのビルドを CI で確認しました。
- ネットからの更新（v2.2.2 → v2.2.3）と、2 つのファイルを一度に書き込む「ファイルから」は、このリリースで実機で確かめます。

## English

### Fixed

- **"From files" with both files sometimes left the old firmware**: with `firmware.bin` and `littlefs.bin` both picked, the web UI is written first, then the firmware. When the web UI request's connection closed, it could stop the firmware write in progress, so the timer got the new web UI but kept the old firmware (the system info then says the firmware and web UI builds differ). A closing connection now stops only its own write.
- After writing only the web UI without a restart, the new web UI is served at once.

### Matching firmware

The receiver and the bridge are unchanged from v2.2.2.

| Device | Firmware |
|---|---|
| XIAO ESP32-S3 (timer) | this release |
| XIAO ESP32-C5 (receiver) | FPVGate C5MK (submodule `e62a635`, unchanged) |
| ESP-NOW bridge (XIAO ESP32-C3 / Wrover-E) | [elrs-netpack v2.11](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.11) (unchanged) |
| netpack XIAO (for WiFi) | [elrs-netpack v2.10](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.10) or later (unchanged) |
| RotorHazard plugin (if used) | [vrxc_elrs v1.1.9](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.9) (unchanged) |

### Updating

- **A v2.2.2 timer**: Settings → "⬆️ ファーム更新" → "🔍 最新版を確認" → "⬇️ v2.2.3 に更新" updates it online (client mode with internet).
- **v2.2.1 or older**: write this release's `firmware.bin` and `littlefs.bin` with "from files", or use the [web flasher](https://yanazoo.github.io/FPV-C5-Lap-Timer/) or PlatformIO. On v2.2.2 or older, write the two files one at a time with "from files", to be safe.

```bash
git fetch && git checkout v2.2.3
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
```

Settings and pilots are kept.

### Verified

- All PC tests pass; the S3, C5 and bridge builds were checked in CI.
- The online update (v2.2.2 → v2.2.3) and "from files" with both files at once are checked on hardware with this release.
