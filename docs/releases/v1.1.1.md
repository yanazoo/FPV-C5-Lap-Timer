## 日本語

多人数で使うときの接続の管理、スタートの待ち時間、設定のバックアップなどを追加し、実機テストで見つかった不具合を直しました。

### 追加：接続の管理

- **管理者（ログインした端末）**：1〜4 台（初期値 2）。上限を超えるログインは、理由のメッセージを出してお断りします。
- **観戦（ログインしていない端末）**：計測時間・ラップ・順位だけの軽い画面です（RSSI と操作ボタンはなく、「👀 観戦」のマークが付きます）。
  - ホストモードは 1〜8 台（初期値 3）。管理者と観戦の合計は 9 台までです（タイマーの WiFi は 10 台まで、うち 1 台は netpack 用）。
  - クライアントモードは 1〜8 台（初期値 6）。
  - 上限を超えると、いちばん古い観戦の接続を切り、「観戦の枠（○○モード：○ 台）」と表示します（「再接続」ボタンあり）。
- **netpack は切りません**：ホストモードで WiFi が満員のときは、ほかの端末を 1 台外して 30 秒入れないようにし、netpack の場所を空けます（管理者の端末は外しません）。
- **ログインの保持**：15 秒・30 秒・1・3・5・10・30 分から選べます。保持時間内なら、ページを読み直してもログインしたままです。
- タイマーの日付は、ログイン中のブラウザーからだけ受け取ります。

### 追加：スタートの待ち時間

- 設定 → 🏁 レース内容で、スイッチで ON / OFF します（初期値 OFF）。待ち時間は 10・15・30・60 秒・任意（1〜600 秒）です。
- スタートボタンでも、ディレクターのプロポスイッチでも、待ち時間の後に「レディ → 3-2-1」に入ります。
- 待っている間は残り時間をオレンジで表示し、最初と 10 秒ごとに「ポーン」の後で「レーススタートまで残り○秒です。」と読み上げます。
- 待っている間にストップ（スイッチを戻す）を押すと、スタートを取りやめます（ゴーグルには何も表示しません）。

### 追加：SD カードへの保存（設定タブの「💾 SDカード」枠）

- **👤 パイロット情報**・**⚙️ 設定情報**（パイロット以外のすべての設定）を保存・復元します。
- **🔳 接続 QR 画像**：印刷・掲示用の PNG を保存します。
- ファイル名には保存した日時が入ります（`pilots_YYYYMMDD_HHMM.csv`、`settings_YYYYMMDD_HHMM.json`、`qr_host_…png` / `qr_client_…png`）。復元のときは、SD カードにある保存ファイルを新しい順に並べて選べます。
- 設定情報と QR 画像には WiFi のパスワードが入るため、ダウンロードはログイン中の管理者だけができます。

### 追加：そのほか

- **接続用 QR コード**（設定タブ）：「WiFi に接続」と「画面を開く」。クライアントモードではルーターの WiFi の QR を出します。
- **＋LAP ボタン**：管理者は、レース中に手動でラップを刻めます。
- **クライアントモードの固定 IP**（初期値は DHCP）。
- **タイマーの再起動ボタン**：後片付けをしてから 2 秒止まり、電源を入れ直したときに近い形で起動します。戻ったら画面が自動で開き直します。
- **🔁 全員の画面を再読み込み**ボタン（管理者のみ）。
- 設定タブの「🔄 再起動」欄に、起動からの時間・起動の理由・空きメモリー・エラーで再起動した回数を表示します。
- タイマーが再起動したら、開いている画面は自動で再読み込みします。
- `.local` で開いたときは IP アドレスへ転送します（PC の Chrome で画面が動かない問題の対策）。

### 修正

- クライアントモードで、ルーターの WiFi の QR コードが出なかった。また OSD テストとお知らせ表示が動いていなかった（API の URL の取り違え）。
- 画面を開いたままタイマーを再起動すると、次のレースの時計が途中（数分後）から始まった。
- 再起動ボタンで再起動すると、電源を抜き差しするまで画面が開けなくなることがあった。
- 観戦の台数を 0 台にできた（ログインもできなくなるため、最小 1 台にしました）。

### 表示から消したもの

- BEST の横の ★BEST／+x.xxxs、観戦画面の「ログインが必要です」の文、タブのロゴ。

### 更新方法

タイマーのファームウェアと Web UI の**両方**を書き込んでください。

```bash
git fetch && git checkout v1.1.1
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
```

ビルド済みのバイナリも添付しています。設定は引き継がれます。Web 画面が開けないときは、`uploadfs` をもう一度行ってください。

## English

Connection management for bigger groups, a start delay, settings backup and more, plus fixes for bugs found in testing on real hardware.

### New: connections

- **Admins** (logged in): 1–4 (default 2). A login past the limit is refused with a message.
- **Viewers** (not logged in): a light screen with the race clock, laps and ranking (no RSSI, no controls, a "👀 観戦" badge).
  - Host mode 1–8 (default 3); admins + viewers at most 9 (the access point takes 10, one is kept for the netpack).
  - Client mode 1–8 (default 6).
  - Past the limit the oldest viewer is closed, with the number of viewer places shown and a reconnect button.
- **The netpack is never cut off**: when the access point is full in host mode, one other station is sent off and kept out for 30 s to make room for it (never an admin's).
- **Login hold**: 15 s, 30 s, 1, 3, 5, 10 or 30 min. A page reload keeps the login.
- The timer takes its date only from logged-in browsers.

### New: start delay

- Settings → 🏁 レース内容: an ON/OFF switch (off by default) and 10, 15, 30, 60 s or any 1–600 s.
- A start from the button or the race director's switch waits, then runs "ready → 3-2-1".
- The time left is shown in orange; at the start and every 10 s a chime is followed by "レーススタートまで残り○秒です。".
- Stop (or switching back) during the wait cancels the start (nothing shown on the goggles).

### New: saving to the SD card (Settings → 💾 SDカード)

- **Pilots** and **settings** (everything but the pilots): save and restore.
- **Connection QR image**: a PNG to print and put up.
- File names carry the date and time they were saved (`pilots_YYYYMMDD_HHMM.csv`, `settings_YYYYMMDD_HHMM.json`, `qr_host_…png` / `qr_client_…png`); Restore lists the saved files, newest first, to pick from.
- Settings files and QR images hold the WiFi password: only a logged-in admin can download them.

### New: other

- **Connection QR codes** (Settings): join the WiFi, open the page; in client mode the router's WiFi.
- **+LAP button**: admins can record a lap by hand during a race.
- **Fixed IP in client mode** (DHCP by default).
- **Restart button**: tidies up, stops for 2 s and starts much like a power-on; the page reopens by itself.
- **🔁 Reload every page** button (admins).
- Settings → 🔄 再起動 shows the uptime, why the timer started, free memory and how many starts followed a crash.
- Pages reload themselves when the timer has restarted.
- A `.local` address is sent on to the IP address (fixes the page not working in Chrome on a PC).

### Fixed

- Client mode: the router's WiFi QR code did not appear; the OSD test and announcements did not work (API routes matched the wrong handler).
- A page left open across a timer restart started the next race's clock minutes in.
- After the restart button the timer could stay unreachable until the power was cut.
- Viewer places could be set to 0 (no one could log in then); the minimum is now 1.

### Removed from the screen

- ★BEST / +x.xxxs next to BEST, the "login needed" line on the spectator screen, the tab icon.

### Updating

Flash **both** the timer's firmware and the web UI.

```bash
git fetch && git checkout v1.1.1
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
```

Prebuilt binaries are attached. Settings are kept. If the page does not open, run `uploadfs` again.
