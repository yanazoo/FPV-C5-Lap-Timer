# FPV C5 Lap Timer v2.0.1 — スタート待ち時間の表示を修正 / Start delay display fix

> **Language / 言語:** [日本語](#日本語) | [English](#english)

---

<a name="日本語"></a>

## 日本語

### 修正

- **スタート待ち時間**を ON にしたとき、待ち時間のカウントが終わって「レディ」の間、計測の表示が `00:01` のまま残っていたのを直しました。
  - 原因：ブラウザーが待ち時間を「知らせを受け取った時刻」から数えていたため、WiFi で届くまでの遅れの分だけタイマー本体より少し遅れて終わっていました。
  - 届くまでの時間を差し引いて数えるようにし、「レディ」の間は `00:00.00`（時間制レースでは制限時間）を表示します。
  - 待ち時間中・レディ中にストップしたときも、表示は `00:00.00` に戻ります。

### 対応するファームウェア

v2.0.0 から変更はありません。

| 機器 | ファームウェア |
|---|---|
| XIAO ESP32-S3（タイマー） | このリリース |
| XIAO ESP32-C5（受信機） | FPVGate C5MK（サブモジュール `e62a635`。変更なし） |
| ESP-NOW ブリッジ（XIAO ESP32-C3 / Wrover-E） | [elrs-netpack v2.9](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.9)（変更なし） |
| netpack XIAO（WiFi で使う場合） | [elrs-netpack v2.7](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.7) 以降（変更なし） |
| RotorHazard で使う場合のプラグイン | [vrxc_elrs v1.1.8](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.8)（変更なし） |

### 更新方法

v2.0.0 からは、Web 画面だけの修正なので `uploadfs` だけで済みます。v2.0.0 より前からの場合は、ファームウェアと Web 画面の**両方**を書き込んでください。

```bash
git fetch && git checkout v2.0.1
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload     # v2.0.0 より前から更新するとき
pio run -e xiao_esp32s3 -t uploadfs
```

ビルド済みのバイナリも添付しています。設定は引き継がれます。

### 動作確認

- PC テストはすべて合格し、S3・C5・ブリッジのビルドを CI で確認しました。
- ブラウザー（モック）で、待ち時間の知らせを遅らせて再現し、修正後は「00:03 → 00:02 → 00:01 → 00:00.00（レディ）→ 3.00」と進むことを確認しました。
- 実機で確認しました。

<a name="english"></a>

## English

### Fixed

- With the **start delay** on, the race clock kept showing `00:01` through "レディ" (ready) after the delay ran out.
  - Cause: the browser counted the delay from when its message arrived, so it ended a little after the timer's, by the WiFi delay.
  - The time the message spent on the way is now taken off, and "レディ" shows `00:00.00` (the time limit in a timed race).
  - A stop during the delay or "レディ" also puts the clock back to `00:00.00`.

### Matching firmware

Unchanged from v2.0.0.

| Device | Firmware |
|---|---|
| XIAO ESP32-S3 (timer) | this release |
| XIAO ESP32-C5 (receiver) | FPVGate C5MK (submodule `e62a635`, unchanged) |
| ESP-NOW bridge (XIAO ESP32-C3 / Wrover-E) | [elrs-netpack v2.9](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.9) (unchanged) |
| netpack XIAO (for WiFi) | [elrs-netpack v2.7](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.7) or later (unchanged) |
| RotorHazard plugin (if used) | [vrxc_elrs v1.1.8](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.8) (unchanged) |

### Updating

From v2.0.0 only the web UI changed: `uploadfs` is enough. From an earlier version, flash **both** the firmware and the web UI.

```bash
git fetch && git checkout v2.0.1
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload     # from before v2.0.0
pio run -e xiao_esp32s3 -t uploadfs
```

Prebuilt binaries are attached. Settings are kept.

### Verified

- All PC tests pass; the S3, C5 and bridge builds were checked in CI.
- In a browser (mock), with the delay message held back: now `00:03 → 00:02 → 00:01 → 00:00.00 (ready) → 3.00`.
- On real hardware.
