# FPV C5 Lap Timer v2.1.0 — 画面の軽量化・iPhone の読み上げ・WiFi クライアントの改良 / Faster web UI, iPhone speech, WiFi client mode

> **Language / 言語:** [日本語](#日本語) | [English](#english)

<a name="日本語"></a>

## 日本語

### 改善：Web 画面が速く開く

- ページを開くときの通信を **15 回 → 2〜3 回** に減らしました。タイマーは通信を 1 つずつさばくので、観戦の端末が多いときほど速くなります。
- タイマーに書き込む Web 画面は、スクリプトをページの中に入れた 1 ファイルにしました（2 回目以降は「変更なし」の 1 回だけ）。
- 設定・パイロット・SD の状態は、接続時に届く最初のメッセージから取ります。

### 修正：iPhone で読み上げが途中で切れる・抜ける

- 読み終わりの合図が来ないことが多い iPhone で、前の読み上げの打ち切り処理が、次のラップの読み上げを途中で止めていました。
- 時間制レースの残り秒数（10〜1）が、Safari で読まれないことがありました。
- 画面ロックやほかのアプリから戻ったあと、読み上げや通過音が止まったままになることがありました（戻ったら画面を 1 回タップしてください）。

### 追加・改善：WiFi クライアントモード

- **ルーターの起動が遅れても、自動でクライアントに戻ります。** ホストに切り替わったあとも、タイマーのアクセスポイントに誰もつないでいない間はルーターを探し、見つかったら自動で再起動してつなぎ直します（レース中・ラップが残っている間、パスワード違いのときは戻りません）。
- **新しい設定「レース中に切れたら」**：レース中（クリアするまでを含む）にルーターとの接続が切れたとき、ホストに切り替えるまでの待ち時間です。15 秒・30 秒・1 分（初期値）・3 分・5 分・待ち続ける、から選べます。待っている間も計測は続きます。
- **つながらない理由を表示します**：設定の WiFi 欄に、「見つからない」「パスワードが違う可能性」「暗号化の方式に対応していない」などと、自動で戻るかどうかを出します。
- いちばん電波の強いアクセスポイントにつなぎます（メッシュ・中継器）。古い暗号化方式（WPA）にも対応しました。

### 修正

- **OSD**：スタートの処理がわずかに遅れると、ARM NOW で出した大会名がレース中も残ることがありました。音の合図の即スタートでも、ゴーグルの時計がブラウザーとそろいます。
- **SD カード**：設定タブ・SD タブを開いている間のカードの確認が、スタートの受け付けや計測の処理を止めていました。
- **長い日本語の名前**：パイロット名・よみかたが日本語 11 文字以上だと文字の途中で切れ、全員の画面が再接続をくり返していました。文字の切れ目で切り、画面でも長すぎる名前を知らせます（日本語 10 文字、英数字 31 文字まで）。
- **パイロットの削除・SD からの復元**：ラップが残っている間は断ります（保存したレースファイルの名前がずれていました）。
- **キャリブレーション**：タイマー本体も Enter ≦ Exit を断ります。パイロットがいないチャンネルのスライダーを動かしたら知らせます。
- **書き込み（`uploadfs`）**：別のプロジェクトを使ったあと、1 回目だけ「`mklittlefs` が見つからない」で失敗していたのを直しました。

### 更新方法

タイマーのファームウェアと Web 画面の**両方**を書き込んでください。

```bash
git fetch && git checkout v2.1.0
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
```

ビルド済みのバイナリも添付しています。設定は引き継がれます（「レース中に切れたら」は 1 分から始まります）。PC に XIAO を複数つないでいるときは、書き込み先を取り違えないよう、ほかの XIAO を外してから書き込んでください。

### 動作確認

- PC テストはすべて合格し（OSD・UTF-8・Web 画面のまとめ方のテストを追加）、S3・C5・ブリッジのビルドを CI で確認しました。
- ブラウザー（モック）で、全タブ・レースの流れ・観戦の再接続・WiFi 欄の表示を確認しました。iPhone の読み上げは、iPhone の動きをまねた読み上げエンジンで比較しました（12 回中 4 回 → 12 回すべて読まれる）。
- 実機で確認しました。

## English

### Faster web UI

- Opening the page takes **2–3 requests instead of 15**. The timer answers them one at a time, so this helps most with many viewers.
- The web UI written to the timer is one page with its scripts inline (a repeat visit is one "not modified").
- Settings, pilots and the SD state come from the first WebSocket message.

### Fixed: iPhone speech cut off or missing

- On iPhone, which often never says an utterance ended, a timer left from the previous call cut off the next lap call.
- The timed race's 10…1 countdown could go unspoken in Safari.
- Speech and gate tones could stay silent after the lock screen or another app (tap the page once when back).

### WiFi client mode

- **Back to the router by itself**: after falling back to its access point, the timer keeps looking for the router while nobody is on the access point, and restarts into client mode once it is there (not during a race or with laps not cleared, not after a wrong password).
- **New setting "レース中に切れたら"**: how long to wait for the router when the link is lost during a race (until cleared) before starting the access point: 15 s, 30 s, 1 min (default), 3 min, 5 min, or as long as it takes. Timing goes on meanwhile.
- **Why it could not join** is shown in the WiFi card (not found, wrong password, security not supported...) and whether it will go back.
- Joins the strongest access point of the network (mesh, repeaters); accepts WPA too.

### Fixed

- **OSD**: a start handled a few ms late left the event name from ARM NOW on the goggles during the race. A start on a sound now shows the same clock on the goggles as in the browsers.
- **SD card**: the card check while the settings or SD tab was open held up start requests and timing.
- **Long Japanese names**: a pilot name or reading of 11 or more Japanese characters was cut in the middle of a character and every page kept reconnecting. Names are cut at character boundaries, and the page says when one is too long (10 Japanese characters, 31 letters).
- **Deleting a pilot / restoring the roster from SD** is refused while the race has laps (the saved race file named the wrong pilots).
- **Calibration**: the timer refuses enter ≤ exit too; moving the sliders of a channel with no pilot says nothing was saved.
- **`uploadfs`**: the first run after another project failed with "`mklittlefs` is not recognized".

### Updating

Flash **both** the timer's firmware and the web UI.

```bash
git fetch && git checkout v2.1.0
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
```

Prebuilt binaries are attached. Settings are kept ("レース中に切れたら" starts at 1 min). With several XIAO boards on the PC, unplug the others first so the right one is flashed.

### Verified

- All PC tests pass (tests added for the OSD, UTF-8 and the web UI build); the S3, C5 and bridge builds were checked in CI.
- In a browser (mock): every tab, a whole race, viewers reconnecting, the WiFi card. iPhone speech compared on a speech engine that behaves like the iPhone's (4 of 12 lap calls → all 12).
- On real hardware.
