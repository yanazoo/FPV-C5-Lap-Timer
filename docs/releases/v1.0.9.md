## 日本語

タイマー・受信機・ブリッジのファームウェアは **v1.0.8 と同じ**です。RotorHazard で使う場合のプラグインを [vrxc_elrs v1.1.8](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.8) に更新しました。

### 修正：RotorHazard＋netpack でディレクターのスイッチが効かない・パイロットのスイッチで動く

- **原因**：プラグインは OSD を送り終えたとき、ブリッジを最後に送ったパイロットの UID のまま待たせていました。
  - ディレクターのスイッチは、ディレクターに OSD を送った直後しか届きませんでした。
  - パイロットが自分の送信機の DVR スイッチを入れると、ディレクターのスイッチとして受け取ることがありました。
- **修正**（vrxc_elrs v1.1.8 と elrs-netpack v2.9 のブリッジの組み合わせ）：
  - ブリッジの受信フィルターで、ディレクターの UID から届いた信号だけを受け取ります。
  - OSD を送っていない間は、ブリッジをディレクターの UID で待たせます。
  - RotorHazard のログに `Bridge listen filter on` と出れば、フィルターが有効です。
- タイマー単体で使う場合は、v1.0.8 のままで変更はありません。

### 対応するファームウェア

| 機器 | ファームウェア |
|---|---|
| XIAO ESP32-S3（タイマー） | v1.0.8 と同じ（このリリースのバイナリでも可） |
| XIAO ESP32-C5（受信機） | FPVGate C5MK（サブモジュール `e62a635`。変更なし） |
| ESP-NOW ブリッジ（XIAO ESP32-C3 / Wrover-E） | [elrs-netpack v2.9](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.9)（変更なし） |
| netpack XIAO（WiFi で使う場合） | [elrs-netpack v2.7](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.7) 以降（変更なし） |
| RotorHazard で使う場合のプラグイン | [vrxc_elrs v1.1.8](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.8)（**更新が必要**） |

### 更新方法

- **タイマー単体で使う場合**：v1.0.8 を書き込み済みなら、作業は不要です。
- **RotorHazard で使う場合**：RotorHazard のサーバーでプラグインを更新します。

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/yanazoo/vrxc_elrs/master/tools/install.sh)
```

ブリッジが v2.9 より前なら、v2.9 に書き換えてください（v1.0.8 の更新方法を参照）。

### 動作確認

- PC テストはすべて合格し、S3・C5・ブリッジのビルドを CI で確認しました。
- vrxc_elrs v1.1.8 の送信データとの比較テストに合格しました。
- vrxc_elrs v1.1.8 のプラグインを PC 上で動かし、フィルターの設定、ディレクターの UID での待機、定期的な送り直しを確認しました。

## English

The timer, receiver and bridge firmware are **the same as v1.0.8**. The RotorHazard plugin moves to [vrxc_elrs v1.1.8](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.8).

### Fixed: the race director's switch with RotorHazard over the netpack

- **Cause**: after an OSD update the plugin left the bridge on the last pilot's UID.
  - The director's switch was heard only right after the director's own OSD update.
  - A pilot's DVR switch could be taken as the director's switch.
- **Fix** (vrxc_elrs v1.1.8 with the elrs-netpack v2.9 bridge):
  - The bridge passes on only frames from the director's UID.
  - Between OSD updates the bridge waits on the director's UID.
  - `Bridge listen filter on` in the RotorHazard log means the filter is on.
- Nothing changes when the timer is used on its own.

### Matching firmware

| Device | Firmware |
|---|---|
| XIAO ESP32-S3 (timer) | same as v1.0.8 (this release's binaries work too) |
| XIAO ESP32-C5 (receiver) | FPVGate C5MK (submodule `e62a635`, unchanged) |
| ESP-NOW bridge (XIAO ESP32-C3 / Wrover-E) | [elrs-netpack v2.9](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.9) (unchanged) |
| netpack XIAO (for WiFi) | [elrs-netpack v2.7](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.7) or later (unchanged) |
| RotorHazard plugin (if used) | [vrxc_elrs v1.1.8](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.8) (**update**) |

### Updating

- **Timer on its own**: nothing to do if v1.0.8 is flashed.
- **With RotorHazard**: update the plugin on the RotorHazard server.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/yanazoo/vrxc_elrs/master/tools/install.sh)
```

A bridge older than v2.9 needs v2.9 (see v1.0.8's update steps).

### Verified

- All PC tests pass; the S3, C5 and bridge builds were checked in CI.
- The cross-check against vrxc_elrs v1.1.8's bytes passes.
- vrxc_elrs v1.1.8 run on a PC: the filter, waiting on the director's UID, and the periodic resends.
