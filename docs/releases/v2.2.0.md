# FPV C5 Lap Timer v2.2.0 — 送信機のリンクでチャンネルを自動割り当て / Automatic channels from the pilots' ELRS links

> **Language / 言語:** [日本語](#日本語) | [English](#english)

---

<a name="日本語"></a>

## 日本語

パイロットの送信機（ELRS バックパック）の電波から、機体とのリンクと VTX の設定を読み取れるようにしました。機体の電源を入れたパイロットを自動でチャンネルに入れ、電源を切ったら外せます。

### 追加：チャンネルの自動割り当て

設定タブ「👥 パイロット情報」の「**チャンネルの割り当て**」で選びます（初期値は「手動」）。

- **自動（ELRS のリンク・レースの合間だけ）**：機体の電源を入れて送信機とリンクが 2 秒続くと、空いているチャンネルに入ります。リンクが切れて 10 秒たつと外れます。レース中・ラップが残っている間は変えず、クリアした後に反映します。
- **自動（ELRS のリンク・レース中も）**：レース中（スタート待ち時間・カウントダウン中も）も入れたり外したりします。外れたパイロットのレースカードと順位は「📴 離脱」として残り、ラップも残ります（SD にも保存）。そのチャンネルはレースが終わるまでそのパイロットのために空けておき、リンクが戻ればそこに戻ります。新しく入る人は、そのレースでまだ使っていないチャンネルに入ります。
- パイロット一覧に「📶 LQ 95」「📴 リンクなし」を表示します。入れないときは理由（VTX 未設定・周波数が重なる・空きチャンネルなし・ほかのパイロットとバインドフレーズが同じ）を出します。
- 8 人を超えたときは、空きが出るまで待ち、先にリンクした人から入ります。
- バックパックの無いパイロットは、手動で選んだチャンネルのままです（手動と自動を混ぜて使えます）。レースディレクターが同じ送信機で飛ぶこともできます。
- ESP-NOW を受信できないとき（ELRS OSD が OFF・ブリッジにつながっていない・ブリッジから応答が無い）は無効になり、手動として動きます（パイロットがチャンネルから外れることもありません）。

### 追加：未登録の送信機から登録

- パイロット情報に無い送信機の電波を受け取ると、「📡 未登録の送信機」の一覧に出ます（登録済みのパイロットとレースディレクターは出ません）。
- 「＋ 登録」で、送信機の VTX が入った登録フォームが開きます。バインドフレーズ（空欄なら名前）を入れると、その送信機と一致するかをその場で表示します。
- バインドフレーズの無い送信機（Lua の Bind ボタンでバインドしたもの）は、「バインドフレーズが無い（送信機の UID で登録）」で登録できます（一覧に「🔑 UID」）。

### 追加：VTX の読み取り

- 送信機の Lua の **VTX Administrator** で Band・Channel を設定していると、リンクしたときと「Send VTx」を押したときに VTX の設定を読み取ります。
- 「**VTX が送信機と違うとき**」：**自動で反映**（初期値）／**タップで反映**（「⚠ 機体の VTX は … ▶ 合わせる」）。レース中・ラップが残っている間はクリア後に反映し、ほかのパイロットと周波数が重なるときは自動では変えません。

### 改善

- パイロット一覧の各行で、状態の表示とチャンネル・編集・削除のボタンの位置をそろえました（スマホ・PC）。
- 設定タブのシステム情報に、**ファームと Web 画面のビルド番号**を表示します。2 つが違うと警告します（`upload` と `uploadfs` の書き込み漏れに気づけます）。
- 新しいタイマー（パイロット情報を一度も保存していないもの）は、パイロット `R2`〜`R5`（Raceband R2〜R5、Ch1〜Ch4、ゴーグル OSD は OFF）が登録された状態で起動します。今お使いのタイマーのパイロット情報は変わりません。

### 修正

- **書き込み（`uploadfs`）**：別のプロジェクトを使ったあと、1 回目に「`mklittlefs` が見つからない」で失敗することがあったのを直しました（開発環境のツールの取り込みを、その場で済ませるようにしました）。

### 更新方法

タイマーのファームウェアと Web 画面の**両方**、それに ESP-NOW ブリッジを書き込んでください。

```bash
git fetch && git checkout v2.2.0
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
pio run -d third_party/elrs-netpack/elrs-espnow-bridge -e xiao_esp32c3 -t upload   # Wrover-E は -e esp32dev
```

ビルド済みのバイナリも添付しています。設定とパイロット情報は引き継がれます（チャンネルの割り当ては「手動」から始まります）。書き込んだら、設定タブのシステム情報で、ファームと Web 画面のビルド番号が同じことを確かめてください。

### 動作確認

- PC テストはすべて合格し（自動割り当て・レース中の割り当て・VTX の番号の変換のテストを追加）、S3・C5・ブリッジのビルドを CI で確認しました。
- ブラウザー（モック）で、自動割り当て（レースの合間・レース中）、未登録の送信機の登録（フレーズの確認・UID）、VTX の反映、ESP-NOW が無いときの無効化、ビルド番号の表示を確認しました。
- ブリッジは、ゴーグルへの OSD の送り方が前の版と 1 バイトも変わらないことを PC で確認しました。
- 実機で、送信機の LQ、自動割り当て（レース中・カウントダウン中を含む）、レースディレクターと同じ送信機のパイロットを確認しました。

<a name="english"></a>

## English

The timer now reads the pilots' radios (ELRS backpacks): whether each radio is linked to its quad, and its VTX settings. A pilot who powers up their quad can be put on a channel by itself, and taken off when the quad goes off.

### New: automatic channel assignment

Settings → 👥 パイロット情報 → "チャンネルの割り当て" (default: manual).

- **自動（レースの合間だけ）** (between races): linked for 2 s, a pilot joins a free channel; not linked for 10 s, they leave it. Nothing changes during a race or while laps are not cleared; it happens after Clear.
- **自動（レース中も）** (also in races, the start delay and countdown included): a pilot who leaves keeps their race card and place as "📴 離脱" with their laps (saved to SD too); their channel is kept for them until the race ends and they go back to it when linked again; newcomers only get channels not used yet in that race.
- The pilot list shows "📶 LQ 95" / "📴 リンクなし", and why a linked pilot can't join (no VTX frequency, the same frequency as a pilot on a channel, no free channel, a bind phrase shared with another pilot).
- With more than 8 pilots, the others wait for a free channel, in the order they linked.
- Pilots without a backpack keep the channel picked by hand. The race director may fly with the same radio.
- Without ESP-NOW (ELRS OSD off, no bridge, or no answer from it) this is off and the timer works as manual (nobody leaves their channel).

### New: register pilots from unregistered radios

- Radios heard that are not on the roster (nor the race director's) are listed under "📡 未登録の送信機".
- "＋ 登録" opens the add form with the radio's VTX filled in; the bind phrase (or name) typed is checked against the radio as you type.
- A radio bound without a bind phrase (Lua Bind button) can be registered by its UID ("🔑 UID").

### New: VTX settings from the radio

- A radio's Lua **VTX Administrator** band/channel is read when it links and on "Send VTx".
- "VTX が送信機と違うとき": apply automatically (default) or on tap ("⚠ 機体の VTX は … ▶ 合わせる"); never during a race (after Clear), never onto a frequency another pilot on a channel uses.

### Improved

- Pilot list rows: badges and the channel / edit / delete buttons line up in every row (phone and PC).
- Settings → system shows the **firmware and web UI build** and warns when they differ (one of `upload` / `uploadfs` missed).
- A new timer (no roster ever saved) starts with pilots `R2`–`R5` (Raceband R2–R5 on Ch1–Ch4, goggle OSD off). Existing rosters are kept.

### Fixed

- **`uploadfs`**: the first run after another project could fail with "`mklittlefs` is not recognized"; the tool install is now finished at once.

### Updating

Flash **both** the timer's firmware and web UI, and the ESP-NOW bridge.

```bash
git fetch && git checkout v2.2.0
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
pio run -d third_party/elrs-netpack/elrs-espnow-bridge -e xiao_esp32c3 -t upload   # Wrover-E: -e esp32dev
```

Prebuilt binaries are attached. Settings and pilots are kept (channel assignment starts as manual). After flashing, check that the firmware and web UI builds match in Settings → system.

### Verified

- All PC tests pass (tests added for automatic assignment, assignment during races and VTX numbers); the S3, C5 and bridge builds were checked in CI.
- In a browser (mock): automatic assignment between and during races, registering unregistered radios (phrase check, UID), VTX settings, the no-ESP-NOW fallback, the build display.
- The bridge's goggle OSD output was checked on the PC to be byte-identical to the previous version.
- On real hardware: radio LQ, automatic assignment (during races and the countdown included), a pilot flying with the race director's radio.
