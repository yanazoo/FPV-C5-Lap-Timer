## 日本語

### 修正：elrs-netpack 経由（WiFi）で自動接続しない

ゴーグル OSD を WiFi（elrs-netpack の XIAO 経由）で使うとき、netpack が再起動したり WiFi から外れたりしても、タイマーは古い TCP 接続を持ったままでした。OSD の書き込みが失敗するまで切断に気づかないため、再接続せず、Web UI の表示も「接続中」のままでした。

- netpack との接続に **TCP keepalive**（5 秒無通信で確認、2 秒間隔で 3 回）を設定しました。切れた接続を約 11 秒で検知し、5 秒ごとの再接続処理でつなぎ直します

**netpack XIAO 側も [elrs-netpack v2.7](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.7) に更新してください。** netpack が設定用 AP から戻らない問題と、新しい接続を受け付けない問題を修正しています。

UART 直結（ESP-NOW ブリッジ）で使っている場合は、今回の変更の影響はありません。

### 対応するファームウェア

| 機器 | ファームウェア |
|---|---|
| XIAO ESP32-S3（タイマー） | このリリース |
| XIAO ESP32-C5（受信機） | FPVGate C5MK（サブモジュール `e62a635`。変更なし） |
| ESP-NOW ブリッジ（XIAO ESP32-C3 / Wrover-E） | [elrs-netpack v2.6](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.6) 以降（ブリッジは v2.7 でも変更なし） |
| netpack XIAO（WiFi で使う場合） | [elrs-netpack v2.7](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.7) |
| RotorHazard で使う場合のプラグイン | [vrxc_elrs v1.1.7](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.7)（変更なし） |

### 更新方法

v1.0.2 から更新する場合は、**S3 のファームウェア**だけを書き込み直してください（Web UI は変更なし）。

```bash
git fetch && git checkout v1.0.3
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
```

ビルド済みバイナリも添付しています（`fpv-c5-lap-timer-v1.0.3-xiao_esp32s3.zip` など）。

### 動作確認

- PC テストがすべて合格、S3・C5・ブリッジのビルドを CI で確認
- 実機で、netpack を先に起動 → 後からタイマーを起動、タイマーの再起動、netpack の再起動のいずれでも自動で接続することを確認しました（netpack v2.7 と組み合わせ）

## English

### Fixed: no automatic reconnect to elrs-netpack over WiFi

With the goggle OSD over WiFi (through the elrs-netpack XIAO), the timer held on to its TCP connection after the netpack rebooted or dropped off WiFi. It only noticed when an OSD write failed, so it never reconnected and the web UI kept showing "connected".

- The netpack connection now uses **TCP keepalive** (5 s idle, 3 probes 2 s apart): a dead connection ends within about 11 s and the 5 s reconnect loop takes over

**Update the netpack XIAO to [elrs-netpack v2.7](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.7) as well.** It fixes the netpack staying in its setup AP for good and refusing a new connection while an old one looked open.

Nothing changes for the UART-wired ESP-NOW bridge.

### Matching firmware

| Device | Firmware |
|---|---|
| XIAO ESP32-S3 (timer) | this release |
| XIAO ESP32-C5 (receiver) | FPVGate C5MK (submodule `e62a635`, unchanged) |
| ESP-NOW bridge (XIAO ESP32-C3 / Wrover-E) | [elrs-netpack v2.6](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.6) or later (the bridge is unchanged in v2.7) |
| netpack XIAO (for WiFi) | [elrs-netpack v2.7](https://github.com/yanazoo/elrs-netpack/releases/tag/v2.7) |
| RotorHazard plugin (if used) | [vrxc_elrs v1.1.7](https://github.com/yanazoo/vrxc_elrs/releases/tag/v1.1.7) (unchanged) |

### Updating

From v1.0.2, flash **the S3 firmware** only (the web UI is unchanged):

```bash
git fetch && git checkout v1.0.3
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
```

Prebuilt binaries are attached (`fpv-c5-lap-timer-v1.0.3-xiao_esp32s3.zip` and the others).

### Verified

- PC tests pass; S3, C5 and bridge builds checked in CI
- On real hardware with netpack v2.7: reconnects on its own when the netpack starts first, when the timer restarts and when the netpack restarts
