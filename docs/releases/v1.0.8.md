<a name="日本語"></a>

## 日本語

### 修正：netpack の接続が途切れる

netpack（WiFi）経由で使うと、接続が途切れ途切れになっていました。特にレース中（ディレクターのスイッチが ON の間）は切れたままで、OFF にすると戻りました。

- **原因**：タイマーは、OSD のデータを小さなパケットに分けて 1 つずつ送っていました。レース中は送信待ちのパケットがたまり、ESP32 の通信処理（lwIP）の送信キューが一杯になります。このとき標準の送信関数は、エラー（`ENOMEM`）を受けて**接続を自分で閉じていました**。
- **修正**：
  - 1 人分の OSD の更新をまとめて、1 回で送るようにしました。
  - 送信キューが一杯のときは、接続を切らずに最大 1 秒待つようにしました。

### 修正：レースディレクターのスイッチが効かない

- **netpack 経由で効かない**
  - **原因**：スイッチの信号は、netpack を通って戻るまでに数十 ms かかります。その間に次の OSD の送信が始まっていると、「待ち受けていない間に届いた」と判断して捨てていました。
  - **修正**：ブリッジ（elrs-netpack v2.9）に受信フィルターを設定し、ディレクターの UID から届いた信号だけを受け取るようにしました。フィルターが有効なら、信号がいつ届いても受け付けます。
- **UART 直結でも効かないことがある**
  - **原因**：ブリッジがタイマーより後に起動したり、再起動したりすると、待機中にディレクターの UID へ戻す処理がありませんでした。
  - **修正**：待機中は 2 秒ごとにブリッジをディレクターの UID に戻し、フィルターも 5 秒ごとに送り直します。
- **UART にブリッジをつないだまま netpack に切り替えた場合**：UART 側のブリッジは専用の UID で待機させ、何も渡さないようにしました。これで netpack 側の邪魔をしません。
- タイマーのシリアルログに `[ELRS] bridge listen filter on` と出れば、ブリッジのフィルターが有効になっています。

### 新機能：誤ったラップの削除

ショートカットなどで誤って記録されたラップを、1 つだけ削除できます。

- **操作**：ログインした状態で、レースカードのラップ行をタップします。確認画面で「削除する」を押します。
- **削除したときの扱い**：
  - **途中の周**：その通過をなかったことにして、次の周と合わせます。トータルタイムは変わりません。
  - **最後の周**：その周を取り消します。
  - **ホールショット**：次の通過をホールショットにします。
- 削除は、全ブラウザー・順位表・ゴーグルの OSD・SD の記録に反映します。

### 修正：iPhone でネットがない場所では読み上げない・声が変わる

- **原因**：ブラウザーが持っている声の一覧から、最初の 1 つを使っていました。その声が端末に入っていない場合（ダウンロードしていない声や、ネットが必要な声）、ネットのない会場では何も読み上げませんでした。また、一覧がまだ届いていないときは声を指定しないまま読み上げていたため、ブラウザーが文ごとに声を選び、パイロットが変わるたびに声が変わっていました。
- **修正**：
  - 端末に入っている声を優先して選びます（Kyoko、Haruka など）。
  - 選んだ声は、すべての読み上げで同じものを使います。
  - 設定タブに「**読み上げの声**」の一覧と「使用中の声」を表示します。ネットが必要な声しかない場合は、注意を表示します。
  - 最初のタップで読み上げを使える状態にします（iPhone）。
  - iPhone のキャプティブポータル画面（Wi-Fi に接続したときに自動で開く簡易ブラウザー）で開いた場合は、Safari で開き直すよう表示します。
- iPhone 向けの読み上げの補正処理は、iPhone でだけ動かすようにしました。PC の Chrome では、この補正が読み上げを最初からやり直させることがあるためです。

> 同じ PC でタイマーの画面を 2 つ（タブやウィンドウ）開いていると、それぞれが読み上げるので 2 回聞こえます。画面は 1 つにしてください。

### 更新方法

**タイマー（ファームウェアと Web UI の両方）**と、**ESP-NOW ブリッジ**（UART 直結のものと netpack 側のもの）を書き込み直してください。

```bash
git fetch && git checkout v1.0.8
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
# ブリッジ（XIAO C3。Wrover-E は -e esp32dev）
pio run -d third_party/elrs-netpack/elrs-espnow-bridge -e xiao_esp32c3 -t upload --upload-port COMx
```

ビルド済みのバイナリも添付しています。設定は引き継がれます。

> 基板（XIAO ESP32-S3）を交換した場合は、設定が初期状態になります。パイロット情報は SD のバックアップから戻せます。ELRS OSD・WiFi・レース内容は設定し直してください。

  - 削除後の OSD の描き直し

<a name="english"></a>

## English

### Fixed: the netpack connection kept dropping

Over the netpack (WiFi), the connection dropped and came back every few seconds. While the race director's switch was on (race running), it stayed down.

- **Cause**: the timer sent each OSD frame as its own tiny TCP segment. During a race, lwIP's send queue filled up, and `WiFiClient::write()` closed the socket on `ENOMEM`.
- **Fix**: each pilot's update now goes out in one send, and a full queue is waited out (up to 1 s) instead of closing the connection.

### Fixed: the race director's switch

- **Over the netpack**: the switch frame came back after the next OSD burst had started, and was dropped as "not listening". The bridge (elrs-netpack v2.9) now passes on only frames from the RD's UID, when the timer asks for it, so a switch frame is accepted whenever it arrives.
- **Over UART**: a bridge that started or rebooted after the timer never heard the switch while idle. The timer now points the bridge at the RD's UID again every 2 s while idle, and resends the filter every 5 s.
- A UART bridge left wired while the netpack is selected is parked: it gets its own UID and passes nothing on.
- `[ELRS] bridge listen filter on` in the timer's serial log means the bridge filter is on.

### New: delete a wrong lap

To remove a lap caused by a shortcut or a false pass:

- **How**: logged in, tap the lap's row on a race card and confirm.
- **What happens**:
  - a lap in the middle: its time joins the next lap, and the total stays the same
  - the last lap: it is dropped
  - the holeshot: the next pass becomes the holeshot
- Every browser, the ranking, the goggles and the SD record follow.

### Fixed: no voice offline on iPhone, and the voice changing between pilots

- **Cause**: the page used the first voice the browser listed. That voice could be one not installed on the device, which says nothing without internet. And when the voice list hadn't arrived yet, no voice was set, so the browser picked a voice per sentence and it changed from pilot to pilot.
- **Fix**:
  - A voice built into the device is used (Kyoko, Haruka, …), the same one for every call.
  - Settings show a "読み上げの声" (voice) list and the voice in use, with a warning when only online voices exist.
  - The first tap unlocks speech on iPhone.
  - A note asks you to open Safari when the page is in the iPhone's captive-portal sheet.
- The iOS speech workarounds now run on iOS only (Chrome on a PC restarted an utterance on resume).

> Two tabs of the timer on one PC each speak, so you hear everything twice. Keep one tab open.

### Updating

Flash **the timer (firmware and web UI)** and **the ESP-NOW bridges** (the UART one and the netpack's).

```bash
git fetch && git checkout v1.0.8
git submodule update --init --recursive
pio run -e xiao_esp32s3 -t upload
pio run -e xiao_esp32s3 -t uploadfs
# bridge (XIAO C3; for Wrover-E use -e esp32dev)
pio run -d third_party/elrs-netpack/elrs-espnow-bridge -e xiao_esp32c3 -t upload --upload-port COMx
```

Prebuilt binaries are attached. Settings are kept.

> A replaced XIAO ESP32-S3 starts from the defaults. Pilots can be restored from the SD backup; set ELRS OSD, WiFi and the race settings again.
